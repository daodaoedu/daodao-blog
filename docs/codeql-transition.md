# Source-aware CodeQL transition

The existing default setup fixes JavaScript languages from legacy main. A data-only content branch has no JavaScript database. The advanced workflow selects tracked regular source files from the immutable checked-out Git commit: Actions when workflows exist, JavaScript/TypeScript when its source extensions exist. Symlinks do not add source languages. No placeholder JavaScript or source exclusion is used.

Both languages run the security-extended query suite. The documented default threat model includes remote sources; this workflow does not add a local-only override. The detector saves the commit/tree, file counts and NUL-delimited full Git tree as an artifact. CodeQL saves generated SARIF, verification metadata, database configuration and logs. Green workflow status alone is not proof that every intended source was extracted: inspect inventory and CodeQL evidence before changing setup.

Uploads are `never` until repository variable `CODEQL_ADVANCED_UPLOAD_ENABLED` is exactly `true`. This allows the existing main JavaScript and new Actions analyses to be proven while default setup remains active. Do not enable uploads while default setup is still configured: GitHub rejects overlapping advanced uploads. Automatic database service uploads are disabled; local SARIF/database-log evidence remains available in the workflow artifacts.

An authorized operator must snapshot the current main SHA/default configuration, confirm fresh successful main analysis evidence, pause conflicting main changes for the transition, disable default setup and read back completion, then enable advanced uploads and run this workflow on the same main. These are separate API writes, not an atomic operation. Read back analysis SHA/ref/languages, security-extended intent and alerts. If the advanced upload fails, roll back in this order: set `CODEQL_ADVANCED_UPLOAD_ENABLED` to `false` and read it back; cancel or drain every advanced run that started with uploads enabled; then restore the captured default setup and read back its successful validation. Confirm the main SHA still matches the intended proof. Finally dispatch a fresh advanced run with the flag false and verify that it analyzes without attempting SARIF submission. Restoring default setup while an enabled advanced run is still active would recreate conflicting uploads. No workflow step changes repository settings, variables, alert dispositions or approvals.
